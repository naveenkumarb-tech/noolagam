Noolagam – Personal Book Tracker
   Noolagam (நூலகம்) means "library" in Tamil.
1. Overview
A multi-user app to track the books people own and read. Each user keeps their own private
library: which books they own, who gifted each book, what they are reading now, and how
much they have read.
     Backend: Python, FastAPI, PostgreSQL, Redis, Celery, Docker
     Frontend: one React codebase that runs as a website AND as an Android app (Capacitor)
     No AI / LLM features
     This is a public GitHub resume project: code quality, structure, tests, observability,
     documentation and clean commit history matter as much as features.

4. Functional requirements
Accounts and authentication
    FR-1: Anyone can sign up with name, email and password.
    FR-2: After sign-up a verification email is sent; until verified the user can log in but sees a
    "verify your email" banner and can resend it.
    FR-3: Log in with email and password.
    FR-4: Stay logged in using access + refresh tokens.
    FR-5: Log out (revokes the refresh token).
    FR-6: Forgot password: enter email, receive a reset link by email.
    FR-7: Reset password from the emailed link; afterwards all other sessions are logged out.
    FR-8: Change password from the profile page (requires current password).
    FR-9: View and edit profile (name).
    FR-10: All book data requires login; each user sees only their own books.
Book management
    FR-11: Add a book with title, author, and optional ISBN, page count, "gifted by".
    FR-12: Look up a book by ISBN to auto-fill details (cover, description, page count) before
    saving.
    FR-13: View all books as a list with covers.
    FR-14: View one book's full details.
    FR-15: Edit a book.
    FR-16: Delete a book (with confirmation).
    FR-17: Record who gave the book, or leave blank if bought.
Reading tracking
    FR-18: Each book has a status: To-read, Reading or Finished.
    FR-19: "Start reading" sets status to Reading and records the start date.
    FR-20: Update current page while reading; show a progress bar and %.
    FR-21: "Mark finished" records the finish date and allows a 1–5 rating.
    FR-22: Add personal notes to a book.
    FR-23: Move a book back to To-read (clears dates and progress).
    FR-24: More than one book can be Reading at the same time.
Browse and search
    FR-25: Filter by status (All / To-read / Reading / Finished) with counts.
    FR-26: Filter by author and by "gifted by".
    FR-27: Search by title, author or description (full-text, ranked).
    FR-28: Sort by date added, title, author or finish date.
    FR-29: Paginate long lists (infinite scroll on the frontend).
Dashboard and stats
    FR-30: Home shows currently reading books with progress and quick actions (Update
    page, Mark finished).
    FR-31: Counts: total owned, finished, reading, to-read, received as gifts.
    FR-32: Stats page per year: books finished, pages read, average days per book.
    FR-33: Books finished per month (bar chart).
    FR-34: Top authors.
    FR-35: People who gifted books, with counts.
Background processing
     FR-36: After a book is added, fetch missing details from Open Library in the background.
     If it fails, retry; the book stays saved without details.
     FR-37: Verification and password reset emails are sent in the background.
Platforms
     FR-38: Works in a web browser on laptop and phone.
     FR-39: The same code builds into an Android app (APK).
5. Non-functional requirements
Performance
     NFR-1: Normal API responses under 300 ms (excluding external lookups).
     NFR-2: Stats cached in Redis per user; invalidated when that user's books change.
     NFR-3: List, filter and search queries use indexes.
Security
     NFR-4: Passwords hashed with bcrypt; never logged or returned.
     NFR-5: Access token ~15 min, refresh token ~7 days, refresh rotation.
     NFR-6: Every book query is filtered by the current user's id; accessing another user's
     book returns 404.
     NFR-7: Rate limiting (Redis) on login, register, forgot-password, resend-verification, per
     IP and per email.
     NFR-8: Verification and reset tokens: random 32 bytes, stored only as SHA-256 hash,
     single use, time-limited (verify 24 h, reset 30 min).
     NFR-9: Forgot-password and resend-verification never reveal whether an email is
     registered (always the same response).
     NFR-10: After a password reset, increment token_version so all existing refresh tokens
     become invalid.
     NFR-11: Secrets only from environment variables; never committed.
     NFR-12: CORS allows only known frontend origins (web URL, Capacitor origins).
     NFR-13: HTTPS in production.
Reliability
     NFR-14: Consistent error format and correct HTTP status codes.
     NFR-15: Background jobs retry with exponential backoff and are idempotent.
     NFR-16: /health (liveness) and /ready (DB + Redis) endpoints.
     NFR-17: Database data persists across container restarts (Docker volume).
Maintainability
     NFR-18: Layered backend: routers → services → repositories.
     NFR-19: Schema changes only through Alembic migrations.
     NFR-20: Type hints everywhere; Ruff passes; TypeScript strict mode.
     NFR-21: Backend test coverage ≥ 70%.
     NFR-22: CI runs lint, tests and builds on every push and pull request.
Observability
     NFR-23: Structured JSON logs with request ID (and user id when known) on every line.
     NFR-24: OpenTelemetry tracing across FastAPI, SQLAlchemy, httpx, Celery.
Usability
     NFR-25: Mobile-first; comfortable one-handed on a phone.
     NFR-26: Start / update page / finish reachable in at most 2 taps from Home.
     NFR-27: Every screen has loading, empty and error states.
     NFR-28: Touch targets at least 44 px; text contrast at least 4.5:1; real buttons, links and
     labelled inputs.
Portability
     NFR-29: Whole stack runs with docker compose up --build .
     NFR-30: API base URL configurable for web and Android builds.
Out of scope (for now)
     AI / LLM features
     iOS app and Play Store publishing
     Offline editing
     Social features (sharing, friends, public profiles)
     Social login (Google etc.)
     Lending tracker (who borrowed my book) – planned for version 2

users

column                 type                    notes

id                     SERIAL PK

name                   VARCHAR(100)            required

email                  VARCHAR(255)            unique, stored lower-case, required

password_hash          VARCHAR(255)            bcrypt

is_verified            BOOLEAN                 default false

token_version          INT                     default 0; bump to log out all sessions

created_at             TIMESTAMPTZ             default now

updated_at             TIMESTAMPTZ             auto update


auth_tokens (email verification + password reset)

column          type                   notes

id              SERIAL PK

user_id         INT FK                 references users.id, ON DELETE CASCADE

purpose         VARCHAR(20)            verify_email / reset_password

token_hash      VARCHAR(64)            SHA-256 of the raw token; raw never stored

expires_at      TIMESTAMPTZ            verify 24 h, reset 30 min

used_at         TIMESTAMPTZ            nullable; single use

created_at      TIMESTAMPTZ            default now


Index: (token_hash), (user_id, purpose).
refresh_tokens

column           type          notes

id               SERIAL PK

user_id          INT FK        references users.id, ON DELETE CASCADE

jti              VARCHAR(64)   unique token id

expires_at       TIMESTAMPTZ

revoked_at       TIMESTAMPTZ   nullable

created_at       TIMESTAMPTZ   default now
books

column                 type                   notes

id                     SERIAL PK

user_id                INT FK                 references users.id, ON DELETE CASCADE

title                  VARCHAR(255)           required

author                 VARCHAR(255)           required

isbn                   VARCHAR(20)            nullable

cover_url              TEXT                   nullable (filled by enrichment job)

description            TEXT                   nullable (filled by enrichment job)

page_count             INT                    nullable, > 0

current_page           INT                    default 0

gifted_by              VARCHAR(255)           nullable (null = bought)

status                 VARCHAR(20)            to_read / reading / finished, default to_read

rating                 SMALLINT               1–5, only when finished

notes                  TEXT                   nullable

started_at             DATE

finished_at            DATE

search_vector          TSVECTOR               generated from title, author, description

created_at             TIMESTAMPTZ            default now

updated_at             TIMESTAMPTZ            auto update


Indexes: (user_id, status), (user_id, author), (user_id, gifted_by), (user_id, created_at), GIN on
search_vector. Check constraints: status values, rating 1–5, current_page >= 0.
Business rules
         To "reading": set started_at = today if empty.
       To "finished": finished_at = today, current_page = page_count (if known), started_at =
       today if empty; rating optional.
       Back to "to_read": clear started_at, finished_at, current_page, rating.
       current_page cannot exceed page_count.
       Rating only allowed when status is finished.
       All logic lives in the service layer, not in routers.

8. Backend architecture
         routers/ → thin HTTP layer (validation, status codes)
         services/ → business logic (status rules, stats, auth flows)
         repositories/ → all DB queries; every book query filtered by user_id
         schemas/ → Pydantic request/response models (never return ORM objects or internal
         fields like password_hash, search_vector)
         Dependency injection with FastAPI Depends (db session, current user, settings)
Middleware and cross-cutting
         Request-ID middleware (accept X-Request-ID or generate; return it; add to every log
         line)
         Structured JSON logging
         Central exception handlers → error format above
    OpenTelemetry instrumentation (FastAPI, SQLAlchemy, httpx, Celery)
    CORS from env
    Redis rate limiting
    Redis caching for stats
9. Background jobs and email
    Celery worker + Redis broker; Celery Beat for scheduled jobs.
     enrich_book(book_id) : Open Library lookup by ISBN, else title + author; fills cover_url,
    description, page_count if empty; then refreshes the search vector. Retries with
    exponential backoff; idempotent.
     send_verification_email(user_id) , send_password_reset_email(user_id) : HTML
    + plain-text Jinja2 templates; retries with backoff.
    Beat (daily): delete expired auth tokens and revoked/expired refresh tokens.
    Email settings from env: SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD,
    EMAIL_FROM, FRONTEND_URL.
    Links: {FRONTEND_URL}/verify-email?token=... , {FRONTEND_URL}/reset-password?
    token=...

    Local dev: Mailpit in docker-compose (SMTP 1025, web UI 8025).
